## Working Method

Across these projects, I use a consistent QA and development loop:

1. Define the intended behavior, scope, and risk.
2. Turn goals into testable scenarios and acceptance criteria.
3. Build or direct the smallest useful implementation.
4. Capture automated checks, generated reports, and observed runtime behavior.
5. Separate confirmed results from open risks and follow-up work.
6. Publish only the artifacts that strengthen review without exposing private project material.

That process reflects the same strengths I bring to professional QA work: systems thinking, test ownership, evidence quality, data interpretation, cross-discipline communication, and clear release decisions.
