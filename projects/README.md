# Project Roadmap

This roadmap is for beginner-friendly projects that build skill gradually. The focus is on learning code, GitHub, documentation, and AI-assisted workflows while staying connected to my love of games and the rebuild after Intrepid closed.

These are not full game projects yet. They are small practice projects that help me build the habits I will need later: organizing files, writing clearly, making simple pages, using GitHub, and reflecting on what I learned.

## Current Project Folders

| Project | Status | Focus |
| --- | --- | --- |
| [QA Bug Report Tool](qa-bug-report-tool/README.md) | First version | Python CLI, pytest, structured Markdown bug reports, and QA note practice |
| [QA Bug Report Portfolio](qa-bug-report-portfolio/README.md) | Planned | Practicing clear bug reports, screenshots, steps to reproduce, and reflection |
| [Unreal Project Showcase](unreal-project-showcase/README.md) | Work in progress | Documenting an Unreal project through development notes, screenshots, QA notes, and reflection |

## Good Starting Point

Start with the [QA Bug Report Tool](qa-bug-report-tool/README.md). It is the first Python CLI project in this portfolio and includes sample notes, generated reports, tests, and documentation.

## 1. GitHub Profile README

### Goal

Create a clear GitHub profile README that explains who I am, why I am learning, how games connect to the journey, and what visitors can expect from this repository.

### Skills Practiced

- Markdown headings, lists, links, and tables
- Writing a beginner-friendly technical profile
- Explaining a learning journey honestly
- Keeping public claims accurate and grounded

### Why It Matters

This is the first thing many visitors may see. It should make the central thread clear: I love games, Intrepid closing forced a reset, and I am rebuilding through code, GitHub, documentation, and AI-assisted learning.

### Suggested Files

- `README.md`
- `AGENTS.md`

### Definition of Done

- The README has a warm introduction.
- The games connection is visible.
- The Intrepid closure is described carefully and professionally.
- The learning goals are clear.
- No skills, jobs, or completed projects are exaggerated.

### Reflection Questions

- Does this README sound like me?
- Is the story honest without being dramatic?
- Can a first-time visitor understand why this repository exists?
- Did I clearly label what is still in progress?

## 2. Learning Log Archive

### Goal

Build a simple archive for weekly learning logs and use it to document early progress.

### Skills Practiced

- Markdown file organization
- Writing weekly reflections
- Linking between files
- Tracking confusion, progress, and next steps

### Why It Matters

Learning logs make progress visible. They help me see what I practiced, what still feels confusing, and how small steps add up over time.

### Suggested Files

- `learning-journey/README.md`
- `learning-journey/logs/2026-05-week-01.md`
- Future files like `learning-journey/logs/2026-05-week-02.md`

### Definition of Done

- The learning journey README explains the purpose of the logs.
- At least one weekly log is filled in with real beginner reflections.
- The log index links to each entry.
- The tone is honest, specific, and not over-polished.

### Reflection Questions

- What did I learn this week?
- What still feels confusing?
- What did I practice?
- How does this connect back to games or rebuilding?

## 3. Simple Portfolio Homepage

### Goal

Create a simple GitHub Pages homepage with plain HTML and CSS that introduces the learning portfolio.

### Skills Practiced

- Basic HTML structure
- CSS layout and responsive design
- Navigation links
- Writing concise page copy
- Connecting a website to GitHub repository content

### Why It Matters

The homepage turns the repository into something easier to browse. It also gives me a small, realistic web project where I can practice structure, style, and clarity without adding frameworks.

### Suggested Files

- `docs/index.html`
- `docs/style.css`

### Definition of Done

- The page has sections for About, Why Games, Learning Journey, Projects, Skills, and Contact.
- The page works on mobile and desktop.
- Links point to the right repository areas.
- The design is clean, readable, and simple.
- The content stays honest about being a learning portfolio.

### Reflection Questions

- Was it clear how HTML and CSS worked together?
- Which part of the layout was hardest?
- Does the homepage feel personal and game-connected?
- What would I improve after learning more CSS?

## 4. Game-Inspired Glossary or Notes Site

### Goal

Create a small notes section that explains beginner coding or GitHub terms using game-inspired comparisons where they help.

### Skills Practiced

- Organizing technical notes
- Writing beginner-friendly explanations
- Using examples and analogies carefully
- Linking between Markdown or HTML pages
- Keeping explanations accurate without getting too advanced

### Why It Matters

Games can make technical ideas easier to remember. A glossary or notes site lets me connect new concepts to something familiar while practicing documentation.

### Suggested Files

- `projects/game-glossary/README.md`
- `projects/game-glossary/terms.md`
- Optional later: `docs/glossary.html`

### Definition of Done

- At least 8 to 10 beginner terms are defined.
- Each term has a plain-language explanation.
- Game-inspired comparisons are helpful, not forced.
- The glossary clearly says it is a learning note, not an expert reference.

### Reflection Questions

- Which terms became clearer after writing them down?
- Did any game comparison make the idea easier to understand?
- Which explanations still need more research?
- How can I improve the notes as I learn more?

## 5. Small Interactive Web Project Inspired by Games

### Goal

Build a very small browser-based interaction inspired by games, such as a click counter, choice tracker, simple inventory list, or progress meter.

### Skills Practiced

- Basic HTML controls
- CSS styling for simple interface states
- Beginner JavaScript, when ready
- Planning a small feature before building it
- Writing a project reflection after testing it

### Why It Matters

This is a first step toward interactive work without trying to build a full game. It keeps the scope small while introducing the idea that software responds to user choices.

### Suggested Files

- `projects/first-interactive-web-project/README.md`
- `projects/first-interactive-web-project/index.html`
- `projects/first-interactive-web-project/style.css`
- Optional when ready: `projects/first-interactive-web-project/script.js`

### Definition of Done

- The project has one clear interaction.
- The page explains what the interaction does.
- The files are simple and organized.
- The README explains the goal, tools used, what was confusing, and what to improve next.
- The project does not try to become a full game yet.

### Reflection Questions

- What did I expect the interaction to do?
- What was confusing about making the page respond?
- How does this connect to game systems or player feedback?
- What is one small improvement I could make next?

## How I Want to Use This Roadmap

- Complete one small project at a time.
- Write a short reflection before moving on.
- Keep project status honest: planned, in progress, or complete.
- Use AI as learning support, not as a way to skip understanding.
- Let game-inspired ideas grow naturally as the basics become stronger.
