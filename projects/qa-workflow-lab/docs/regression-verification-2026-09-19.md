## Defects Reproduced and Fixed

| ID | Risk and reproduction | Correction and regression evidence |
| --- | --- | --- |
| QWL-01 | AI8 trusted an accepted dependency even when its acknowledgement, evidence or build was invalid. Downstream work could appear available. | Validate current-build evidence and acknowledgement, then propagate blockers through dependency order. Direct, indirect, reordered and valid-control tests pass. |
| QWL-02 | Null, empty, whitespace or numeric telemetry identity fields reached SQLite. Missing event IDs undermined reliable deduplication. | Reject invalid configuration, metric and event identities before SQL. Twelve invalid-identity cases, duplicate controls and query-parameter tests pass. |
| QWL-03 | Malformed provider envelopes, content or encodings could raise incidental exceptions instead of a controlled adapter error. | Validate response structure and token accounting, normalize decoding failures and retain sanitized errors. Mocked failures verify no retry or exception-detail disclosure. |

The focused negative run reproduced 26 failing parameterized cases across these three groups. They pass after correction. Tests disable socket connections and remove inherited model credentials; provider behavior is exercised with injected transports.

Two test-runner setup issues were corrected separately: the initial pytest output parent did not exist, and autogenerated parameter IDs for oversized payloads exceeded practical Windows limits. The command harness also needed a per-command Git safe-directory setting under the sandbox account. None required changing application behavior. Earlier logs remain in the local evidence archive rather than being silently replaced.

## Reproduce

Run from the project directory after the documented editable installation. Choose new output paths:

```powershell
python -m pytest -q --junitxml=runs/regression-results.xml
python -m qa_workflow_lab demo --output runs/candidate-review
python -m qa_workflow_lab demo --case evidence-gaps --output runs/gaps-review
python -m qa_workflow_lab demo --case corrected-model --output runs/corrected-review
python -m pytest runs/candidate-review/test_regression_candidate.py
python -m qa_workflow_lab evaluate --output runs/contract-results.json
python -m qa_workflow_lab package --output packages/verified-showcase.zip
node tests/browser_check.cjs ../../docs/qa-workflow-lab.html runs/browser-review ../../docs/index.html
```

The gaps command returns 2 by design. For individual roles, use `run --input sample-data/candidate.json --workflow AI1 --output runs/ai1-review`, substituting AI1 through AI8 and each sample case. Browser setup is described in [Verification Scope](verification.md).

## Scope and Remaining Checks

- Screenshots were inspected at desktop and narrow mobile widths. Automated viewport checks used 320, 390, 414, 768, 1024, 1440 and 2560 pixels.
- The standalone showcase made no remote resource requests during its browser test. All model transport tests were mocked.
- No live model reasoning evaluation, real game build, issue tracker, build farm, deployment or production load test was performed.
- Chrome resizing is not a substitute for physical-device, Safari/Firefox or screen-reader testing. This is not a full accessibility certification.
- Contract cases and fault injections establish the listed behaviors, not a coverage percentage or an exhaustive proof of correctness.
- Public fixtures are fictional. Package contents are restricted to this project's source, tests, documentation and sample outputs.
