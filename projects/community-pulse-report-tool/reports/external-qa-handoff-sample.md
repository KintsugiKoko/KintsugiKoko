# External QA Handoff Sample: Community Pulse

> Portfolio-safe sample export generated from fictional local CSV feedback. This is a human-reviewed handoff artifact, not Jira integration, live platform ingestion, or automated triage.

## Purpose

This sample shows how manually prepared community feedback records can become QA-ready context for a partner review. It uses fictional data only and keeps the handoff compact enough for QA, design, production, community, or External QA partners to inspect.

## Suggested QA Follow-up

- Treat onboarding clarity as the first review target because it has the strongest negative signal in the sample.
- Use fishing timing and Starwell offerings as focused follow-up checks, not broad feature conclusions.
- Confirm whether each quote fairly represents the local sample before sharing externally.
- Keep ownership notes human-reviewed before routing to QA, design, production, community, or External QA partners.

## Limitations

- Built-in sample data is fictional.
- Counts and priorities summarize only the provided local records.
- This handoff does not use real player data, real platform data, proprietary systems, private tools, generated screenshots, generated evidence, or generated art.
- This handoff does not scrape, monitor, fetch, discover, or ingest live community conversations.
- This handoff does not perform automated moderation, automated player decisions, or Jira updates.
- A human reviewer owns context, priority, routing, and final wording before this becomes an actual QA handoff.
