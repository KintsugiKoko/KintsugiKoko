# External QA Process Notes

This document explains the QA thinking behind the External QA Handoff Manager prototype.

## Why Handoffs Matter

External QA work is only useful when testers have clear goals, stable setup instructions, and evidence standards. Vague instructions often create vague bugs, duplicate noise, or reports that developers cannot act on.

## What A Good Packet Protects

- Developer time
- QA lead review time
- External tester focus
- Release-readiness communication
- Bug database quality
- Cross-discipline owner routing

## QA Lead Intake Review

The intake step is where QA leadership turns incoming reports into usable signal. A bug can be real and still need more information before it should reach developers.

The prototype checks for build and platform context, repro clarity, expected vs. actual behavior, evidence, repro rate, known issue match, duplicate risk, and likely owner routing.

## Portfolio-Safe Scope

This project uses fictional feature data. It does not describe or recreate a private studio outsource process. It is a public demonstration of QA lead judgment, bug-quality standards, and communication structure.
